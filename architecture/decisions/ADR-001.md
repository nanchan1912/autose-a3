# ADR-001: Four agent roles, with the tester separate from the implementer

Status: Accepted
Date: 2026-11-24
Decision: D1 (Splitting the work)

## Context

The workflow must carry an issue through six fixed stages (requirements, design, implementation,
testing, release, review). Each stage requires a different kind of reasoning: turning an informal
issue into testable criteria, planning a change against the existing architecture, editing code,
writing tests that check the criteria, and judging someone else's change.

## Decision

We use four agent roles, each a separate headless Claude Code process with its own system prompt,
tool allow list and output schema:

| Role | Stages |
|---|---|
| Analyst | 1 Requirements (reusing the A1 skill) and 2 Design (reusing the A2 ARCHITECTURE.md), as two separate sessions |
| Implementer | 3 Implementation |
| Tester | 4 Testing (writes the tests from the acceptance criteria) |
| Reviewer | 6 Review, in its own job (see ADR-008) |

Stage 5 (push, pull request, CI) has no agent; it is ordinary code.

## Alternatives considered

- **One agent for everything.** Rejected: it could allow mistakes to go unnoticed, because the same
  agent would write the code and judge it.
- **One agent per stage (six agents).** Rejected: more agents would increase cost and coordination
  overhead without necessarily improving quality.
- **Implementer writes its own tests.** Rejected: separating the tester from the implementer reduces
  confirmation bias, since the tester can independently verify whether the implementation satisfies
  the requirements. This alternative is tested as variant `E2-self-test` (experiment E2).

## Consequences

- Each stage gets a role-specific prompt and only the tools it needs (ADR-005).
- A separate tester costs an extra agent call per run, and a test can disagree with the
  implementation; the implementer can raise a `test_disputes` entry that the tester re-checks once.
- The analyst does both requirements and design, so the design is written by the agent that
  analysed the issue, but in a fresh session that gets only the spec document (ADR-003).
