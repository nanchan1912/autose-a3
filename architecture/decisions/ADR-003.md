# ADR-003: Each agent receives only the artifacts its stage needs

Status: Accepted
Date: 2026-11-24
Decision: D3 (Hand-offs)

## Context

Every stage produces something the next stage needs, but passing everything along (full
conversations, all earlier reasoning) lets later agents simply agree with earlier ones and makes
contexts large.

## Decision

Hand-offs are structured documents (JSON matching a schema per stage, rendered as `spec.md`,
`design.md`, ...), never an agent's conversation:

| Agent | Receives | Deliberately does not receive |
|---|---|---|
| Analyst, requirements | sanitised issue + maintainer comments (marked untrusted), read access to the repo | comments from non-maintainers |
| Analyst, design | issue, spec, ARCHITECTURE.md, the repo; on revision the failure or review findings | the requirements conversation |
| Implementer | spec, design; on retries build errors, failing tests or review findings | the analyst's conversation |
| Tester | acceptance criteria, the design's test plan, names of the changed files | the implementer's notes |
| Reviewer | issue + maintainer comments, the PR diff, the repo at the PR head, the test-suite result | spec, design, PR description, any agent conversation (ADR-008) |

## Alternatives considered

- **Passing full artifacts and conversations to every later agent.** Rejected: it encourages agents
  to blindly agree with previous agents and adds unnecessary context and token usage.

## Consequences

- Giving each agent only the information necessary for its stage reduces bias. Keeping the tester
  independent of the implementer's notes encourages it to identify problems on its own.
- Less context means fewer tokens per call.
- An agent sometimes has to re-read code that an earlier agent already read.
- Variant `E1-sees-rationale` gives the reviewer the author's PR description, to measure what this
  decision is worth (experiment E1).
