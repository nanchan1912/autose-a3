# ADR-004: Stage documents as workflow artifacts, code and tests on the PR branch

Status: Accepted
Date: 2026-11-24
Decision: D4 (State)

## Context

Information has to survive between stages, between the jobs of a run (build, review, later rounds)
and between runs, and anyone should be able to follow what happened.

## Decision

- Each stage document (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`),
  the agent transcripts and the token ledgers are uploaded as workflow artifacts
  (`autose-build-rK`, `autose-release-rK`, `autose-review-rK`, `autose-summary`, 90-day retention).
  Later rounds download them.
- Code and tests live on the branch `autose/issue-N` and its pull request. No pipeline documents are
  committed to that branch.
- A new trigger on the same issue restarts from stage 1 and force-pushes the branch, updating the
  same pull request.

## Alternatives considered

- **A separate database or store.** Rejected: artifacts already provide a record of what happened at
  each stage without requiring a separate database.
- **Resuming a partially completed run.** Rejected in favour of restarting from the beginning.

## Consequences

- Restarting from the beginning gives a clean and predictable execution rather than risking
  inconsistent state from a partially completed run; the cost is repeating stages that had passed.
- Keeping documents out of the branch means the reviewer's checkout contains only code and tests.
- Artifacts expire after 90 days; links in `results/runs.md` stop working after that.
