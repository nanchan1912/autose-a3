# ADR-005: Agents can read files and run Python; git and GitHub stay with workflow code

Status: Accepted
Date: 2026-11-24
Decision: D5 (Tools)

## Context

Agents generate code and read untrusted issue text. Whatever tools they have can be used wrongly,
either by mistake or because of instructions hidden in an issue.

## Decision

- Agents are Claude Code CLI 2.1.330 processes started with `--restricted` (file tools confined to
  the working copy), `--tools` (only the listed built-in tools exist), an `--allowedTools` list with
  `--permission-mode dontAsk` (anything else is refused and logged), and no MCP servers or web tools.
- Analyst: Read, Glob, Grep. Implementer and tester: also Edit, Write and
  `python -m unittest | py_compile | flake8 | -c`. Reviewer: Read, Glob, Grep, `python -m unittest | -c`.
- No agent has git, the GitHub CLI, the GitHub API or a GitHub token. Commits, pushes, PR creation and
  comments are done by workflow code (`gitops.py`, `ghapi.py`) in steps that run no agent.
- After each agent, code reverts edits outside its area: implementer outside production code,
  tester outside `tests/`, anyone in `.github/`, `workflow/` and other protected paths.

## Alternatives considered

- **Giving agents git and GitHub access** (gh CLI, GitHub MCP server). Rejected: it widens what an
  agent that generates incorrect code or follows malicious instructions can do.

## Consequences

- Restricting agents limits the damage an agent can cause if it generates incorrect code or follows
  malicious instructions.
- Git operations, commits and PR creation under workflow control make the process safer and more
  auditable: every commit and PR has a fixed format.
- Agents cannot use arbitrary shell commands; a refused call (for example `cd x && ...`) costs a turn.
  The prompts tell them to run one plain command per call.
