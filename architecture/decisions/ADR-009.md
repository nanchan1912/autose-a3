# ADR-009: Explicit budgets, timeouts and input checks

Status: Accepted
Date: 2026-11-24
Decision: D9 (Safety and failures)

## Context

Agents can spend money without limit, retry forever, hang, or follow instructions hidden in issue
text, and anyone can write an issue.

## Decision

- **Budgets:** per agent call (`--max-budget-usd`: analyst $1, implementer $2.50, tester $1.50,
  reviewer $3), per build job $8, per run $20 (ledgers of earlier rounds are summed); `--max-turns`
  per role; retry limits (ADR-002).
- **Timeouts:** per agent process (15-25 min), per job (`timeout-minutes`: build 90, review 45).
- **Input checks:** issue text is cleaned (hidden HTML comments, invisible characters removed),
  scanned for injection patterns (high-risk ones stop the run before any agent sees it), and wrapped
  in `<untrusted>` tags that every prompt says to treat as data. Only maintainer comments are used.
- **Isolation:** agents have no GitHub token and no git (ADR-005); the orchestrator and prompts are
  always taken from the default branch; pull requests from forks are refused.

## Alternatives considered

- **Unlimited execution until the agent finishes.** Rejected: unpredictable cost.

## Consequences

- The biggest concern is uncontrolled agent behaviour: unexpected API spending, infinite retries and
  malicious instructions hidden in issue descriptions. Explicit limits, timeouts and input checks
  reduce these risks.
- Strict limits may occasionally stop a run that could have succeeded with more time or resources;
  this is accepted, because predictable costs and security are more important than unlimited
  execution.
- Remaining risk: an agent allowed to run `python -c` could still read the model credential from its
  environment and use the network; the spending limit bounds the damage.
