# ADR-010: Only maintainers can trigger; runs on the same issue queue

Status: Accepted
Date: 2026-11-24
Decision: D10 (Triggers)

## Context

The workflow starts from GitHub events. Issues and comments can be written by anyone, and two runs
on the same issue could start at the same time.

## Decision

- **Triggers:** label `autose` on an issue, or a comment `/autose [variant=NAME]` (on a PR it starts
  a review only), or `workflow_dispatch` from the Actions tab.
- **Who:** the gate job checks that the comment author is OWNER/MEMBER/COLLABORATOR and has
  write/maintain/admin permission; labels can only be added by people with triage access or more;
  bot comments and comments from others are ignored.
- **Concurrency:** one concurrency group per issue/PR number with `cancel-in-progress: false`, so a
  second run waits. Events that are not autose commands get a unique group so they cannot cancel a
  waiting run. Experiment variants use their own branches.

## Alternatives considered

- **Anyone can trigger.** Rejected: arbitrary users should not be able to consume API credits or
  trigger code modifications, and issues and comments can contain untrusted instructions.
- **Cancel the running run when a new one starts.** Rejected in favour of queuing.

## Consequences

- Queuing prevents two executions from modifying or evaluating the same issue simultaneously, which
  avoids race conditions and inconsistent results, even if some runs have to wait.
- GitHub keeps at most one waiting run per group; a third trigger replaces the waiting one.
