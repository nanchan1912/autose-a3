# ADR-012: Deterministic stage checks are code and need their own tests

Status: Accepted (amends ADR-007)
Date: 2026-11-24
Decision: D7 (Checks)

## Context

ADR-007 made every stage check deterministic code, on the grounds that code checks are objective and
reproducible. In the first batch of runs the build check (`check_build`) compared only committed
changes, but it runs before the commit, so it rejected every first implementation attempt even when the
implementer's edit was correct (fixed in PR #22). The design check also rejected two E2 designs
(I3, I4) for naming a documentation section that did not exist, which was correct behaviour but cost a
retry each time.

## Decision

Keep deterministic checks (ADR-007 stands), but treat each check as production code: every check gets
unit tests in `workflow/autose_tests/` against known-good and known-bad stage outputs, and a change to a
check is validated on a plumbing run before experiment runs.

## Alternatives considered

- **Replace the faulty checks with an LLM judge.** Rejected: the bug was in our code, not in the idea of a
  deterministic check; a judge would make failures harder to reproduce.

## Consequences

- "Deterministic" does not mean "correct": a buggy check fails consistently, which skews the
  stage-pass statistics (implement passed on the first attempt in only 3 of 11 runs, mostly because of
  this bug).
- More test code to maintain, but a wrong check is caught before it distorts an experiment.
