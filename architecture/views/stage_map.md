# Stage map: agent, artifact and check per stage

| # | Stage | Who does the work | Input it gets | Artifact | Check before moving on (who decides) | On failure |
|---|---|---|---|---|---|---|
| 1 | Requirements | Analyst agent (Sonnet 5.5, read-only), using the A1 `requirements-specification` skill | Sanitised issue + maintainer comments (untrusted-delimited), repository (read) | `spec.md` (+ `spec.json`) | `check_spec` (code): every AC has given/when/then, a concrete observable `then`, no vague words, no AC resting on an ASSUMPTION; or status BLOCKED | Retry once with the check's problems. BLOCKED: stop and post the clarification questions on the issue. Otherwise stop. |
| 2 | Design | Analyst agent (fresh session, read-only), using the A2 `ARCHITECTURE.md` | spec, issue, repository, ARCHITECTURE.md; on a revision: the failure or review findings | `design.md` (+ `design.json`) | `check_design` (code): every file exists (or is `create`), every named function/class exists (or is `new`), only allowed paths, every AC has a planned test | Retry once with feedback, then stop. |
| 3 | Implementation | Implementer agent (Sonnet 5.5, edits production code only) | spec ACs, design; on retries: build errors / failing tests / review findings | `diff.patch` (+ `build_check.md`) | `check_build` (code): `pip install -e .`, `compileall`, import + convert smoke test, no new flake8 findings in changed files, diff not empty and under 800 lines; edits under `tests/` or protected paths are reverted | Retry (max 3 attempts per design), then back to stage 2 once, then stop. |
| 4 | Testing | Tester agent (Sonnet 5.5, edits `tests/` only), separate from the implementer | spec ACs, design test plan, names of changed files (not the implementer's notes) | `test_report.md` (+ `test_results.json`) | `run_tests` (code): full suite passes (old + new) and every AC id has a passing test named `test_ac_00N_*`; tester may not delete existing tests | Broken/missing tests: tester fixes once. Failing tests: back to stage 3 (within its attempts), then stage 2 once, then stop. |
| 5 | Release | No agent: release step + `ci.yml` + release_check job | branch from stage 4 | `pr.md` + PR link (+ `release_check.md`) | PR is open at the tested commit and `ci.yml` (tests on Python 3.11 and 3.13, flake8 errors) is green (code); sets commit status `autose/ci` | Stop and report. |
| 6 | Review | Reviewer agent (Opus 5.5) in its own job, fresh context, no push | issue + maintainer comments, PR diff, repository at PR head, test-suite result | `review.md` (+ `review.json`), posted as a PR review | Verdict is computed by code from the agent's findings: request changes if any blocking/major finding with evidence, or the suite fails, or tests were deleted, or protected paths changed; else approve | Request changes: new round resumes at the earliest route among the findings (design / implement / test). At most 2 rework rounds (3 reviews), then hand over to a person. |
| - | Hand-over | finalize job | all artifacts of the run | `run_summary.json`, comment on issue and PR | - | A person decides: merge, close, or answer and re-run. |
