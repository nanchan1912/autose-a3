The docstring of `AbbrExtension.load_glossary` says *"Any abbreviations that already exist will be overwritten."* That is not what happens for me.

We build one `Markdown` instance at start-up and later load project specific glossaries into it:

```python
import markdown
from markdown.extensions.abbr import AbbrExtension

ext = AbbrExtension(glossary={'HTML': 'Old title', 'CSS': 'Cascading Style Sheets'})
md = markdown.Markdown(extensions=[ext])

ext.load_glossary({'HTML': 'Hyper Text Markup Language'})
md.reset()
print(md.convert('HTML and CSS'))
```

Output:

```html
<p><abbr title="Old title">HTML</abbr> and <abbr title="Cascading Style Sheets">CSS</abbr></p>
```

Expected `title="Hyper Text Markup Language"` for HTML (CSS should stay as it is). Calling `load_glossary` twice has the same problem: the first value always wins.

Please keep the current behaviour where a glossary loaded *before* the extension is added to `Markdown` takes priority over the `glossary` config option, we rely on that too. And abbreviations defined inside a document (`*[HTML]: ...`) should still win for that document.
